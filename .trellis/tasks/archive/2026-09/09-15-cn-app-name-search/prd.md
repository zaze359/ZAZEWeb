# 需求：国内应用按名搜索与应用宝详情补全

## 背景与问题

管理后台添加国内应用时，管理员必须**人工用百度搜索**该应用、找到 APK 或包名，再手工填写表单
（或上传 APK 解析）。这是当前添加国内应用最大的摩擦点。

现有能力（子任务 `09-15-cn-store-metadata`）已支持「本地选 APK → 前端解析 → 自动填充」，但它要求
管理员**先自己找到并下载 APK**——只解决了「填」，没解决「找」。

## 已验证的技术事实（实测 2026-09-15）

### 服务端「按名搜索」这条路走不通

| 渠道 | 实测结果 |
|---|---|
| 应用宝 `sj.qq.com/myapp/searchDetail.htm?kw=` | 返回**首页** SSR（`page=/`、`scene=home`），搜索结果客户端渲染 |
| 应用宝 `_next/data/<buildId>/…json` | 同样返回首页壳页 |
| 小米 `app.mi.com/searchAll?keywords=` | 返回首页推荐，「微信」仅出现在页脚链接 |
| 华为 `web-drcn.hispace.dbankcloud.cn` | `rtnCode 1002 InterfaceCode Verification failed`（需签名） |
| 酷安 `api.coolapk.com` | 403 |
| 360 手机助手 / 豌豆荚 | 无包名，前端渲染 |
| OPPO / vivo / 应用汇 / 安智 | 404 或无法连接 |
| APKPure / APKMirror / APKCombo | 境外，连接失败 |

**结论：国内主流商店均不在服务端提供可用的按名搜索接口。**

### 但应用宝「详情页」是服务端渲染的

`https://sj.qq.com/appdetail/<packageName>` 返回约 300KB HTML，内嵌 `__NEXT_DATA__` JSON，
按包名可拿到完整元数据。实测 `com.tencent.mm`：

```
name=微信  pkg_name=com.tencent.mm  version_name=8.0.77
apk_size=278623416  icon=http://pp.myapp.com/ma_icon/0/icon_10910_1788258461/256
developer=深圳市腾讯计算机系统有限公司  cate_name=社交
description=你可以通过音视频通话、群聊、朋友圈…   update_time=1788258482
download_num=8977275013  average_rating=4.30  md_5=FDD4F4BECE4E5C872A74690FDF30DC72
```

**无 `version_code` 字段**，只有 `version_name` + `update_time` + `md_5`；
**无 APK 直链**（`apk_url` / `download_url` 为空），只能提供详情页链接。

## Goal

让管理员输入「微信」就能直接找到并导入应用，元数据（版本名 / 大小 / 图标 / 简介 / 开发商 / 分类）
全部自动补全，**不需要百度搜索，也不需要准备 APK**。

## 方案（已与用户确认）

1. **本地词典**解决「应用名 → 包名」：内置常见国内应用 name→packageName 映射，支持模糊匹配，
   毫秒级、离线可用、零外部依赖。未命中时引导上传 APK（走已有能力）。
2. **应用宝详情页**解决「包名 → 元数据」：新增应用宝上游，按包名抓取 SSR 详情页解析完整元数据。
3. **图标**：应用宝走 CDN URL（`pp.myapp.com`，仅几十字节）；APK 解析的 data URI 作为兜底。

## In Scope

- 内置词典文件（常见国内应用 **96 条**，经应用宝逐条校验），加载后在 `searchByName` 中优先返回候选
- 新增应用宝上游：`lookup` 链末尾回退；`importApp(source=应用宝)` 时抓取详情补全
- 已存在应用走 **upsert**：补全元数据 + 追加真实版本
  （可修复 seed 中 41 个应用的「官方最新版」占位版本与 favicon 图标）
- 管理端搜索结果展示来源标记（本地词典 / 应用宝 / F-Droid / IzzyOnDroid）

## Out of Scope

- 商店按名搜索的抓取（实测不可行）与无头浏览器方案（依赖重、易失效、合规风险）
- APK 直链下载（应用宝详情页不提供）
- 批量补全全部已有应用（本次只做单个导入/补全，批量作为后续）
- 修改 F-Droid / IzzyOnDroid 现有链路

## 验收标准

- **AC1** 输入「微信」「抖音」等常见国内应用名，即时返回候选（名称 + 包名 + 来源=本地词典），
  无需联网搜索，结果中不再只有开源应用
- **AC2** 词典候选一键导入 → 新建应用，名称 / 版本名 / 大小 / 图标 / 简介 / 开发商 / 分类
  均来自应用宝，**不是占位值**；并自动补应用宝详情页下载源
- **AC3** 对已存在应用（如 seed 中的微信）导入 → 补全图标 / 简介 / 开发商 / 分类 + 追加真实版本，
  原有数据不丢失
- **AC4** 词典包名有误（应用宝查无此包）→ 明确报错「应用宝未找到该包名」，**不写入脏数据**
- **AC5** 应用宝不可达 / 超时 → 优雅降级：词典候选仍能返回，仅导入阶段提示失败，不影响其他上游
- **AC6** 词典结果与外部上游按 packageName 去重，同一应用只出现一次
- **AC7** 图标策略：应用宝来源存 CDN URL；APK 导入仍写 data URI（真实图标不退化）

## 风险

1. **依赖应用宝页面结构**：`__NEXT_DATA__` 变更会导致解析失败。缓解：解析失败等价于「未找到」，
   优雅降级不写库；前端提示可改用 APK 导入。
2. **词典准确性**：包名可能有误或应用已下架。缓解：词典只提供**候选包名**，实际名称与元数据以
   应用宝返回为准，管理员导入前可见预览；词典条目在生成时逐条用应用宝**校验**。
3. **长尾覆盖不足**：冷门 / 企业内部应用词典没有。缓解：未命中时引导上传 APK。
4. **合规**：仅按包名读取公开详情页，无反爬对抗、无高频请求（结果内存缓存 30min）。
